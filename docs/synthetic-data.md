# Synthetic Data in MEVA

MEVA currently uses **only synthetic (fake, computer-generated) patient data**.
No real patient data is included anywhere in this project.

## Where the data comes from

There are two kinds of synthetic FHIR data in this repo:

1. **Handmade examples** (`data/synthetic/patient-001.json` and
   `data/synthetic/patient-001-fhir.json`) — small, simple files written by
   hand for Stage 1 and Stage 2, to make the basic FHIR structure easy to
   learn.

2. **Synthea-generated fixtures** (`data/synthetic/synthea/`) — realistic
   FHIR R4 Bundles produced by [Synthea](https://github.com/synthetichealth/synthea),
   an open-source, Apache-2.0-licensed synthetic patient generator. Synthea
   creates entirely fictional patients with realistic (but fake) medical
   histories, using statistical models — it never uses real patient records.

   **As of Stage 8A.1, all 21 patients here (`patient-01.json` through
   `patient-21.json`) were generated locally by this project**, directly
   from the official `synthetichealth/synthea` generator (tag `v3.4.0`,
   Apache License 2.0), using a fixed, documented, reproducible command and
   seed. Full generation details — exact revision, command, seed, export
   settings, selection process, and per-file SHA-256 hashes — are in
   [`data/synthetic/synthea/PROVENANCE.md`](synthetic/synthea/PROVENANCE.md).

   **This replaces an earlier set of 18 patients** (used throughout Stages
   3–8A) that had been copied from a separate repository,
   `synthetichealth/synthea-sample-data`, which currently has no declared
   license. Those files are no longer part of MEVA's public dataset — see
   [`docs/historical-sample-data-provenance.md`](historical-sample-data-provenance.md)
   for their identity (filenames and hashes only, no content) and why they
   were removed, and [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)
   for the full licensing analysis. All historical benchmark results
   (v0.1–v0.3) that used those files remain valid as historical development
   records — they are not rewritten or reattributed to the new dataset.

## Why synthetic data for development

- **No privacy risk.** Since no real patient ever existed, there's nothing
  to protect or leak.
- **No legal/compliance burden.** Working with real patient data requires
  strict handling rules (e.g. HIPAA in the US). Synthetic data avoids that
  entirely while MEVA is still an early, experimental project.
- **Realistic enough to be useful.** Synthea data has the same structure
  and messiness as real hospital FHIR data (missing fields, varied coding
  systems, multiple encounters over years), so code written against it is
  much more likely to work with real systems later.

## Important note

Synthea patients are **entirely fictional**. Names, dates, conditions, and
medications are all generated by statistical models and do not represent
any real person, living or dead.
